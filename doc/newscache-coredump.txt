		      NewsCache - coredump - A Short Guide
		      ====================================

							   Author Herbert Straub
						  e-mail: herbert@linuxhacker.at
								Date: 2004-06-10
				    (updated for the current packages)

1) Compiling Newscache with --enable-debug
------------------------------------------

./autogen
./configure --prefix=/usr --sysconfdir=/etc --enable-debug
make
su -c 'make install'



2) Run NewsCache as root
------------------------

Core dumps are only written if the process runs as root (or the kernel is
set to dump processes that changed their user, see fs.suid_dumpable). Set
the keywords Username and Groupname in /etc/newscache.conf to root for the
test.



3) Allow core dumps
-------------------

With systemd (the Debian and Fedora packages), add this to the service
(systemctl edit newscache):

[Service]
LimitCORE=infinity

and restart the service. debian/newscache.service is the packaged unit.

With the optional SysV script (--enable-sysv-init, etc/NewsCache.init.in)
or when you start newscache by hand, run

ulimit -c unlimited

in the same shell before the daemon start line.



4) Wait for the coredump
------------------------

If the NewsCache process crashes with a segfault (for example), the core
goes where the kernel puts it: see /proc/sys/kernel/core_pattern. The
daemon does not change into the spool directory, so a plain pattern like
"core" means the directory the daemon was started in. With systemd-coredump
use

coredumpctl list newscache



5) Analyse
----------

gdb /usr/sbin/newscache
(gdb) core /path/to/core
(gdb) bt

or, with systemd-coredump:

coredumpctl gdb newscache
(gdb) bt

Then you should see the stacktrace. Report it at
https://github.com/go-while/NewsCache/issues.
